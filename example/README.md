# 使い方

## 必要環境

Node.js 20.0.0 以降（LTSの22で動作確認済み）。

## セットアップ

`example` は npm で公開されている `richflyer@2.0.0` を利用します。

```
cd example
npm install
```

## 検証アプリ（index.js）

SDKが提供する全APIをメニューから対話的に実行できる検証アプリです。

```
npm start
```

### 認証情報の指定

以下の環境変数を設定しておくと、起動時の入力プロンプトのデフォルト値として使われます。
未設定の場合は都度入力してください（環境変数を設定しなくても検証は可能です）。

| 環境変数 | 内容 |
| --- | --- |
| `CUSTOMER_ID` | カスタマーID |
| `SERVICE_ID` | サービスID |
| `API_KEY` | 管理API実行キー |
| `SDK_KEY` | SDK実行キー |
| `TEMPLATE_ID` | テンプレートID（投稿系APIのデフォルト値） |

#### 書き場所1: `.env` ファイル（おすすめ）

`example/.env` に書くのが最も手軽です。`env.sample` をコピーして値を書き換えてください。

```sh
cd example
cp env.sample .env
```

```ini
# example/.env
CUSTOMER_ID=aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa
SERVICE_ID=bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb
API_KEY=cccccccc-cccc-cccc-cccc-cccccccccccc
SDK_KEY=dddddddd-dddd-dddd-dddd-dddddddddddd
TEMPLATE_ID=eeeeeeee-eeee-eeee-eeee-eeeeeeeeeeee
```

`.env` は `.gitignore` 済みなのでコミットされません。`index.js` が起動時に自動で読み込みます
（追加のパッケージは不要です）。

#### 書き場所2: コマンドラインで指定

一時的に別の値で試したいときに便利です。**`.env` の値より優先されます。**

```sh
CUSTOMER_ID=xxx SERVICE_ID=xxx API_KEY=xxx SDK_KEY=xxx npm start
```

※ いずれの方法でも、認証情報をソースコード（`.js`）にハードコードしないでください。

### 実行できるAPI

- 認証: IDトークン取得
- メディア: メディア登録/アップロード
- 投稿: テンプレート取得 / 投稿登録 / 投稿登録（セグメント値ファイル利用） /
  投稿承認ステータス更新 / 分散投稿中止 / 投稿送信結果取得
- 単発投稿: 単発投稿登録 / 単発投稿キャンセル
- セグメント: 管理情報一覧取得 / 説明登録 / 表示状態登録

### IDの引き継ぎ

直前の実行結果（メディアID・投稿詳細ID・単発投稿ID・セグメント名）を保持し、
次の操作の入力プロンプトのデフォルト値として表示します。
そのため、以下のような一連の流れをIDのコピペなしで検証できます。

- メディア登録 → 投稿登録 → 投稿承認ステータス更新 → 投稿送信結果取得
- 単発投稿登録（遅延配信あり） → 単発投稿キャンセル
- セグメント管理情報一覧取得 → セグメント説明登録 / 表示状態登録

なお、投稿詳細IDは**本登録**時のみ応答されます（下書き登録時は編集URLが返ります）。
承認ステータス更新の検証をする場合は、下書きにせず「承認をスキップ」もしない設定で登録してください。
単発投稿IDは**遅延配信を指定した場合のみ**応答されるため、キャンセルを検証する場合は遅延配信を指定してください。

### セグメント値の指定

「投稿登録」では、配信対象セグメントの値をカンマ区切りで直接入力できます。

「投稿登録（セグメント値ファイル利用）」では、セグメントキーごとに
「ファイルで指定」と「値を直接指定」を選べます。
ファイルを指定した場合は、値を記載したテキストファイルが自動で添付されます
（値を半角スペース・改行・カンマ区切りで格納してください）。
